# سَلِس حلول — Cloud Kitchen Subscription System

مشروع Next.js واحد يخدم الثلاثة أقسام:

- `/` — الموقع التسويقي العام
- `/admin` — لوحة تحكم المطعم (إدخال الوجبات، إدارتها)
- `/order-app` — تطبيق العميل (تصفح واختيار الوجبات) — قابل للتثبيت على الجوال (PWA) عبر `src/app/manifest.ts`

## التشغيل محلياً

```bash
npm install
npm run dev
```

يفتح على `http://localhost:3000`

## ربط قاعدة البيانات (Supabase)

المشروع حالياً يشتغل ببيانات تجريبية (Demo Data) بدون أي إعداد. لربطه بقاعدة بيانات حقيقية:

1. أنشئ مشروع مجاني على [supabase.com](https://supabase.com)
2. روح لـ SQL Editor ونفّذ محتوى ملف `supabase/schema.sql` — ينشئ الجداول (العملاء، الوجبات، الاشتراكات، الطلبات، سجل الأحداث)، و2 Views (خطة إنتاج الغد، وجدولة التوصيل حسب الحي)، **ويفعّل Row Level Security مع السياسات** (القسم 6 في الملف)
3. انسخ `.env.example` باسم `.env.local` وحط فيه رابط ومفتاح مشروعك (تلقاهم في Project Settings → API)
4. أعد تشغيل `npm run dev` — بيتصل تلقائياً بدل البيانات التجريبية

| الطبقة | التقنية | ليش |
|---|---|---|
| الواجهة (الثلاث أقسام) | Next.js 16 + React 19 + TypeScript + Tailwind 4 | مشروع واحد بدل ثلاثة، أسرع بناء |

## حالة الأمان — اقرأ هذا قبل الإطلاق

| الطبقة | الحالة |
|---|---|
| Row Level Security على كل الجداول | ✅ مفعّل مع سياسات (القسم 6 في `schema.sql`) |
| بيانات العملاء (جوال/إيميل/عنوان/هدف صحي) | ✅ ممنوعة تماماً على المفتاح العام |
| قراءة الوجبات المتاحة للعميل | ✅ مسموحة (وهذا المطلوب) |
| الكتابة في قاعدة البيانات من المتصفح | ✅ ممنوعة على المفتاح العام |
| فصل الأدوار في `/admin` | ⚠️ على مستوى الشاشات فقط — **بدون كلمة مرور** |

**الفجوة الوحيدة الباقية:** بوابة الأدوار في `/admin` تمنع الوصول عبر الواجهة، لكنها محفوظة في
المتصفح — يعني مو حماية فعلية. وبما إن السياسات تمنع الكتابة على المفتاح العام، فإن إضافة وجبة
من لوحة الجودة بترجع خطأ صلاحية بعد ربط Supabase (الوجبة تبقى في قائمة الانتظار ويظهر السبب).

لإغلاق الفجوة، اختر مساراً من الاثنين الموضّحين في نهاية القسم 6 في `supabase/schema.sql`:
Supabase Auth مع جدول `staff`، أو Route Handler على الخادم بمفتاح `service_role`.

## عمليات المطبخ (`/admin/ops`)

وحدة العمليات مبنية على ملف العمليات (الإكسل): المنيو، المكوّنات، الوصفات، الدوران، خطة الإنتاج والمشتريات، بطاقة المطبخ، بوابات الجودة، التسعير، وهندسة المنيو.

- **البيانات الأصلية:** `src/data/ops/*.json` — مُصدَّرة من الإكسل بالسكربت `scripts/ops/export_data.py`:
  `python3 scripts/ops/export_data.py <ملف.xlsx> src/data/ops <expected.json>`
- **محرك الحساب:** `src/lib/ops/engine.ts` — يطابق صيغ الإكسل (تغذية، تكلفة، سعر، هامش، حساسية، مشتريات).
- **الأدوار والصلاحيات:** `src/lib/ops/roles.ts` — جدول واحد يحدد مين يشوف ومين يعدّل، وبوابة `src/components/ops/AdminGate.tsx` تطبّقه على كل صفحات `/admin`.
- **التعديلات:** `src/lib/ops/store.ts` — تُحفظ مؤقتاً في المتصفح (localStorage) مع سجل تعديلات، لحد ربط Supabase.

> الأدوار حالياً فصل على مستوى الواجهة فقط (بدون تسجيل دخول). الحماية الفعلية تحتاج Supabase Auth وصلاحيات على مستوى قاعدة البيانات (RLS).
