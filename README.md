# سَلِس حلول — Cloud Kitchen Subscription System

مشروع Next.js واحد يخدم الثلاثة أقسام:

- `/` — الموقع التسويقي العام
- `/admin` — لوحة تحكم المطعم (إدخال الوجبات، إدارتها) — **تتطلب تسجيل دخول كمشرف**
- `/order-app` — تطبيق العميل (تصفح واختيار الوجبات) — يشتغل كـ PWA على الجوال فوراً

## التشغيل محلياً

```bash
npm install
npm run dev
```

يفتح على `http://localhost:3000`

## ربط قاعدة البيانات (Supabase)

المشروع حالياً يشتغل ببيانات تجريبية (Demo Data) بدون أي إعداد. لربطه بقاعدة بيانات حقيقية:

1. أنشئ مشروع مجاني على [supabase.com](https://supabase.com)
2. روح لـ SQL Editor ونفّذ محتوى ملف `supabase/schema.sql` — هذا ينشئ كل الجداول (العملاء، الوجبات، الاشتراكات، الطلبات، سجل الأحداث) بالإضافة لـ 2 Views جاهزة (خطة إنتاج الغد، وجدولة التوصيل حسب الحي)
3. **نفّذ بعدها `supabase/02-security.sql`** — يفعّل Row Level Security وسياسات الوصول. بدونه أي زائر يقدر يقرأ ويكتب في كل الجداول، لأن مفتاح anon موجود داخل حزمة المتصفح
4. انسخ `.env.example` باسم `.env.local` وحط فيه رابط ومفتاح مشروعك (تلقاهم في Project Settings → API)
5. أنشئ مستخدم مشرف: Authentication → Users → Add user، وبعدها نفّذ في SQL Editor:
   ```sql
   insert into public.admin_users (user_id, role)
   select id, 'owner' from auth.users where email = 'you@example.com'
   on conflict (user_id) do update set role = 'owner';
   ```
6. أعد تشغيل `npm run dev` — بيتصل تلقائياً بدل البيانات التجريبية، وتقدر تدخل `/admin` بعد تسجيل الدخول من `/login`

> ملاحظة: `/admin` محمية دائماً. إذا Supabase غير مربوط، التحويل يكون لصفحة `/login` ولا تفتح اللوحات — هذا مقصود (المنع هو الأصل).

## البنية التقنية

| الطبقة | التقنية | ليش |
|---|---|---|
| الواجهة (الثلاث أقسام) | Next.js 16 + TypeScript + Tailwind | مشروع واحد بدل ثلاثة، أسرع بناء |
| قاعدة البيانات | Supabase (Postgres) | جاهز فوراً بدون بناء Backend من الصفر، فيه Realtime |
| الخط | Cairo (مستضاف محلياً) | خط عربي احترافي حديث، بدون اعتماد على إنترنت خارجي وقت البناء |
| الأتمتة (لاحقاً) | n8n | يتصل بـ Supabase عبر Webhooks لأتمتة الإشعارات وخطة الإنتاج |

## الأمان

ثلاث طبقات تحمي بيانات العملاء، وكل طبقة مستقلة عن الثانية:

| الطبقة | المكان | تحمي من |
|---|---|---|
| Row Level Security | `supabase/02-security.sql` | أي قراءة أو كتابة غير مصرّح بها — هذي الطبقة الحاسمة، تشتغل في قاعدة البيانات نفسها |
| فحص المشرف في الخادم | `src/lib/auth.ts` (`verifyAdmin`) — يُستدعى في كل صفحة تحت `/admin` | مستخدم مسجّل لكن مو مشرف |
| فحص مبدئي | `src/proxy.ts` | زائر بدون جلسة (تحويل سريع لـ `/login` بدون استعلام قاعدة بيانات) |

ملاحظات للمساهمين:

- أي صفحة جديدة تحت `/admin` لازم تستدعي `await verifyAdmin("/admin/...")` في `page.tsx`. الفحص **ما ينفع** في `layout.tsx` — الـ layout ما يُعاد تشغيله عند التنقل داخل التطبيق.
- أي جدول جديد لازم `enable row level security` + سياسة صريحة. بدون سياسة = ممنوع، وهذا المطلوب.
- أي `create view` جديد على جدول فيه RLS لازم `set (security_invoker = on)`، وإلا الـ view يتجاوز RLS.
- مفتاح `service_role` يتجاوز RLS بالكامل — ما ينزل في كود يوصله المتصفح أبداً.
- القواعد الكاملة في `CLAUDE.md`.
