# Food Style — نظام المطبخ السحابي

مشروع Next.js واحد يخدم ثلاثة أقسام:

- `/` — الموقع التسويقي العام
- `/admin` — لوحات فريق العمل (عمليات المطبخ، الجودة، الإدارة التنفيذية)
- `/order-app` — تطبيق العميل، قابل للتثبيت على الجوال (PWA)

كل البيانات من قاعدة بيانات حقيقية. ما فيه بيانات تجريبية ولا محاكاة في أي شاشة.

---

## إعداد المشروع من الصفر

### 1) أنشئ مشروع Supabase

اذهب إلى [supabase.com](https://supabase.com) وأنشئ حساباً ومشروعاً جديداً.
اختر منطقة قريبة (Frankfurt أو Mumbai أقرب للسعودية) واحفظ كلمة مرور قاعدة البيانات.

### 2) نفّذ السكيما

من لوحة Supabase → **SQL Editor** → **New query**، الصق محتوى `supabase/schema.sql`
كاملاً ونفّذه. ينشئ:

- جدول `staff` بالأدوار الثلاثة، وجدول `customers` مرتبطاً بحسابات المصادقة
- جداول العمليات (المكوّنات، المنيو، الوصفات، الدوران، الإعدادات، البوابات، الإنتاج، السجل)
- جدولَي سلامة الغذاء (سجل الحرارة، دفعات الصلاحية)
- **36 سياسة RLS** تحدد مين يقرأ ومين يكتب إيش بالضبط

### 3) حمّل بيانات العمليات

في نفس SQL Editor، نفّذ `supabase/seed.sql` — يحمّل بياناتكم الفعلية من ملف الإكسل:
**53 صنف · 80 مكوّن · 457 سطر وصفة · 14 يوم دوران**.

الملف idempotent: تقدر تنفّذه مرة ثانية بأمان لو حدّثتم الإكسل. لإعادة توليده:

```bash
python3 scripts/ops/gen_seed.py
```

### 4) اربط التطبيق

من Supabase → **Project Settings → API** انسخ القيمتين:

```bash
cp .env.example .env.local
```

وعبّي:

```
NEXT_PUBLIC_SUPABASE_URL=https://xxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJhbGci...
```

> `.env.local` مستثنى في `.gitignore` — لا ترفعه للمستودع أبداً.

### 5) أضف حسابات فريق العمل

**العملاء يسجّلون بأنفسهم من `/signup`. الموظفون لا — تضيفهم أنت يدوياً**، وهذا مقصود:
لو كان التسجيل مفتوحاً للموظفين، أي شخص يصير مطبخاً أو تنفيذياً بنفسه.

1. Supabase → **Authentication → Users → Add user**
2. حط الإيميل وكلمة المرور، وفعّل **Auto Confirm User**
3. انسخ الـ UID، وفي SQL Editor:

```sql
insert into staff (user_id, role, name)
values ('<UID>', 'executive', 'اسم الموظف');
```

الأدوار: `executive` أو `kitchen` أو `quality`.
لإيقاف موظف بدون حذفه: `update staff set active = false where user_id = '<UID>';`

### 6) شغّل

```bash
npm install
npm run dev
```

يفتح على `http://localhost:3000`

## الأدوار والصلاحيات

| | الإدارة التنفيذية | المطبخ | الجودة والمتابعة |
|---|---|---|---|
| خطة الإنتاج والمشتريات | عرض | **تعديل** | عرض |
| الوصفات وجدول الدوران | عرض | **تعديل** | عرض |
| القيم الغذائية والحساسية | عرض | عرض | **تعديل** |
| بوابات الجودة (0–6) | — | — | **تعديل** |
| بوابة السعر والهامش (7) | **تعديل** | — | — |
| أسعار المكوّنات | **تعديل** | — | — |
| الإعدادات وهندسة المنيو | **تعديل** | — | — |
| سجل التعديلات | عرض | — | — |
| سجلات سلامة الغذاء | **تعديل** | **تعديل** | **تعديل** |

**الفصل مفروض في قاعدة البيانات نفسها، مو في الواجهة.** أي تعديل خارج صلاحية الدور
ترفضه Postgres حتى لو عُدّلت الواجهة أو استُدعيت الـ API مباشرة.

نقطة مهمة: **ما يُنشر صنف للعميل إلا باتفاق دورين** — الجودة تعتمد البوابات 0–6،
والإدارة التنفيذية تعتمد بوابة السعر (7). ولا دور واحد يقدر ينشر لحاله.

## حالة الأمان

| الطبقة | الحالة |
|---|---|
| تسجيل دخول حقيقي بالإيميل | ✅ Supabase Auth، الجلسة في كوكي HttpOnly |
| الأدوار | ✅ من جدول `staff` عبر جلسة مُوقَّعة — مو من المتصفح |
| حماية `/admin` | ✅ تُفحص في `proxy.ts` قبل إرسال الصفحة + في الـ layout + في قاعدة البيانات |
| Row Level Security | ✅ 36 سياسة على كل الجداول، المنع هو الأصل |
| بيانات العملاء | ✅ كل عميل يشوف صفه هو فقط |
| الكتابة من المتصفح | ✅ كلها عبر Server Actions، والدور يُقرأ على الخادم |
| سجلات سلامة الغذاء | ✅ للإضافة فقط — ما تُعدَّل ولا تُحذف بعد الحفظ |

## البنية التقنية

| الطبقة | التقنية |
|---|---|
| الواجهة | Next.js 16 (App Router) + React 19 + TypeScript + Tailwind 4 |
| قاعدة البيانات والمصادقة | Supabase (Postgres + Auth + RLS) |
| الخط | Cairo، مستضاف محلياً |

**ملفات مهمة:**

- `src/lib/ops/engine.ts` — محرك الحساب: دوال صافية بلا React ولا متصفح، تطابق صيغ
  الإكسل (تغذية، تكلفة، سعر، هامش، حساسية، مشتريات، هندسة المنيو). قابلة للاختبار وحدها.
- `src/lib/ops/server-data.ts` — قراءة بيانات العمليات من قاعدة البيانات.
- `src/app/admin/ops/actions.ts` — كل تعديلات العمليات كـ Server Actions مع فحص الدور والسجل.
- `src/lib/ops/roles.ts` — جدول الصلاحيات (نسخة الواجهة من سياسات RLS).
- `src/proxy.ts` — تجديد الجلسة وحماية المسارات. (اسمه `proxy` مو `middleware` لأن
  Next 16 هجر الاسم القديم.)
- `supabase/schema.sql` — السكيما والسياسات.
- `supabase/seed.sql` — بيانات العمليات، مُولَّدة آلياً.
